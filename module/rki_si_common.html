public pure function si_bsub_ml_conflict(bsub_fill, n_sub, use_multilayer, nz) result(conflict)

The CONSERVATION conflict predicate (shared by both backends’ enable guards): the linear subgrid b_sub fill (n_sub >= 2) is incompatible with the multilayer (nz > 1) wet/dry step. The free-surface solve conserves the subgrid wetted volume v_cell(eta) = mean_s max(eta - b_sub_s, 0), but the ML thickness update + recovery Dirichlet ghost consume max(eta - b, 0) on the PLAIN bed; under linear these diverge across the partial-flooding band => mass leaks at the wet/dry front. flat + ML (b_sub == b, conservative) and linear + 2D (barotropic uses v_cell throughout) both return .false. A v_cell-consistent ML update is a documented deferred limitation; until then callers must reject a .true. combination fail-loud. Pure so tests can assert it directly (the enable path error-stops, which cannot be caught in-process).
